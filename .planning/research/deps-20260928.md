## Key findings

1. `qrcode` 0.14.1 is the canonical QR encoder: MIT OR Apache-2.0, MSRV 1.67.1, features `default = ["image","svg","pic"]`, only optional normal dep is `image ^0.25`. Fact. Sources: https://crates.io/api/v1/crates/qrcode (max_stable 0.14.1, updated 2024-07-05), https://docs.rs/qrcode/0.14.1/qrcode/ (deps + `QrCode::new` / `render::<Luma<u8>>` / string render), https://github.com/kennytm/qrcode-rust
2. `fast-qr` 0.14.0 is the active styled alternative: MIT, MSRV 1.59, updated 2026-09-01, zero mandatory deps (optional `resvg ^0.45.1`, `wasm-bindgen`), `QRBuilder::new().build()` + `convert::svg::SvgBuilder` / `convert::image::ImageBuilder` with `Shape::RoundedSquare`. Fact. Sources: https://crates.io/api/v1/crates/fast-qr, https://docs.rs/fast_qr/latest/fast_qr, https://github.com/erwanvivien/fast_qr
3. `qrcodegen` 1.8.0 (nayuki port) is the zero-dependency fallback: MIT, 2022-04-17, ~10M downloads, dormant but stable. Fact. Source: https://crates.io/api/v1/crates/qrcodegen
4. `qrcode-svg` 2.x belongs to a different fork ecosystem (`houseme/qrcode-rs`: `qrcode-core`/`qrcode-render` split), not a plugin for `kennytm/qrcode-rust`. Do not pair `qrcode-svg 2.1.1` with `qrcode 0.14.1`. Fact. Sources: https://crates.io/api/v1/crates/qrcode-svg (2.1.1, deps `qrcode-core ^2.1.1` + `qrcode-render ^2.1.1`, repo `houseme/qrcode-rs`), vs finding 1 repo `kennytm/qrcode-rust`
5. For gpui-kit 0.6.6 (Apache-2.0, 2026-09-21, repo `longbridge/gpui-kit`): README claims "built-in charts" plus a `system_monitor` example ("real-time charts with CPU/memory data"), and the one-dependency recipe is `gpui-kit = "0.6"`. Fact. Sources: https://github.com/longbridge/gpui-kit (README Features + Usage + Examples), https://crates.io/api/v1/crates/gpui-kit, https://crates.io/api/v1/crates/gpui-component
6. There is no maintained general-purpose Rust sparkline crate: `sparkline` 0.1.1 (MIT) last touched 2015; `leptos-sparkline` is Leptos/canvas-specific; `embedded-graphics-sparklines` is embedded-only. Inference: hand-rolled GPUI canvas (Path/polyline) is the right default for in-app sparklines; `plotters` 0.3.7 (MIT, 2024-09-08) fits export/offscreen PNG via `ChartBuilder` + bitmap backend, then feed bytes to GPUI image. Inference (exact GPUI image/SVG element name not verified in this read-only pass; verify against gpui-kit docs before coding). Sources: https://docs.rs/qrcode/0.14.1/qrcode/, https://docs.rs/fast_qr/latest/fast_qr, https://crates.io/api/v1/crates/image
8. `tempfile` 3.27.0 is canonical: MIT OR Apache-2.0, MSRV 1.63, default feature `getrandom`, deps `fastrand`/`rustix`/`windows-sys`; API `tempfile()` / `NamedTempFile::new()` / `tempdir()` / `Builder` / `spooled_tempfile()`; temp files private-by-default, temp dirs inherit umask. `tempdir` 0.3.7 (2018) is deprecated — do not use. Fact. Sources: https://crates.io/api/v1/crates/tempfile, https://docs.rs/tempfile/latest/tempfile/ (Design/Security/Access Permissions/Examples)

Fact. Sources: https://crates.io/api/v1/crates/aho-corasick, https://docs.rs/aho-corasick/latest/aho_corasick/

Fact + Inference (selection rule). Sources: https://crates.io/api/v1/crates/memchr, https://crates.io/api/v1/crates/regex, https://crates.io/api/v1/crates/daachorse

Fact. Sources: https://crates.io/api/v1/crates/getrandom, https://docs.rs/getrandom/latest/getrandom/, https://crates.io/api/v1/crates/rand
12. `zeroize` 1.9.0 (Apache-2.0 OR MIT, 2026-06-12, MSRV 1.85, `RustCrypto/utils`) gives `Zeroize::zeroize()`, `Zeroizing<T>` auto-zero-on-drop wrapper, and `derive(Zeroize, ZeroizeOnDrop)`; `secrecy` 0.10.3 (Apache-2.0 OR MIT, 2024-10-09, dep `zeroize ^1.6`) adds `SecretBox`/`SecretString` + `ExposeSecret` with `Debug` redaction. Rule: wrap owned secrets in `Zeroizing`/`SecretBox`, don't hand-roll volatile writes. Fact. Sources: https://crates.io/api/v1/crates/zeroize, https://docs.rs/zeroize/latest/zeroize/, https://crates.io/api/v1/crates/secrecy, https://docs.rs/secrecy/latest/secrecy/

Real icacls equivalents (`/grant`, `/deny`, `/reset`) need `SetNamedSecurityInfoW`/`SetSecurityInfo`/`ConvertStringSecurityDescriptorToSecurityDescriptorW`, best accessed via the maintained `windows` 0.62.2 crate (MIT OR Apache-2.0, 2025-10-06, `microsoft/windows-rs`). Assumption (API surface from platform knowledge; exact `windows`-crate module path to confirm at implementation time). Sources: https://crates.io/api/v1/crates/windows, https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls, https://doc.rust-lang.org/std/fs/index.html

Avoid `windows-acl` 0.3.0 (MIT, 2021-01-11, `trailofbits/windows-acl`) and `windows-permissions` 0.2.4 (MIT, 2021-06-29) for new code: ergonomic but stale ~5 years, pre-`windows`-crate era (`winapi`-pinned). Fact. Sources: https://crates.io/api/v1/crates/windows-acl, https://crates.io/api/v1/crates/windows-permissions, https://blog.trailofbits.com/2018/08/23/introducing-windows-acl-working-with-acls-in-rust (age/context)

## Area details

### 1. QR generate + render (desktop app)

**A. `qrcode` 0.14.1 — primary (RECOMMENDED)**
- Version: 0.14.1. License: MIT OR Apache-2.0. MSRV 1.67.1. Repo: https://github.com/kennytm/qrcode-rust
- Maintenance: mature/stable; last publish 2024-07-05; ~20.8M total downloads; edition 2021. Not monthly-active, but the de-facto standard with huge reverse-dependency base.
- Why best: smallest API that covers need (`QrCode::new` / `with_version` + `EcLevel`), built-in `svg` + `pic` + `image` render paths, `image ^0.25` optional (disable `default-features` if image unwanted), Micro-QR support.
- Usage pointer: https://docs.rs/qrcode/0.14.1/qrcode/ — `QrCode::new(b"01234567")` → `code.render::<Luma<u8>>().build()` → `.save("/tmp/qrcode.png)`; string path `code.render().light_color(' ').dark_color('#').build()`; SVG path via `svg` feature + `svg::Color`.
- Cargo pointer: `qrcode = { version = "0.14.1", default-features = false, features = ["svg"] }` then add `"image"` only if raster needed (verify feature set at pin time).

**B. `fast-qr` 0.14.0 — styled alternative (RECOMMENDED when QR must look branded)**
- Version: 0.14.0. License: MIT. MSRV 1.59. Repo: https://github.com/erwanvivien/fast_qr/
- Maintenance: active; published 2026-09-01; ~387K downloads; 100% documented on docs.rs.
- Why best: speed-focused, `Shape::RoundedSquare` styling, explicit `svg` (`SvgBuilder`) vs `image` (`ImageBuilder` on `resvg`) feature split, WASM path; benches compare against `qrcode ^0.14.1` (dev-dep, so author tracks parity).
- Usage pointer: https://docs.rs/fast_qr/latest/fast_qr — `QRBuilder::new("https://example.com/").build()` → `SvgBuilder::default().shape(Shape::RoundedSquare).to_file(&qrcode, "out.svg")`; image: `ImageBuilder::default().shape(...).background_color([255,255,255,0]).fit_width(600).to_file(&qrcode, "out.png")`; features `image = ["svg","dep:resvg"]`, `svg`, `wasm-bindgen`.
- Caveat: `image` feature pulls `resvg ^0.45.1` — heavier than `qrcode`+`image`; choose per binary-size budget. Fact (dep range from crates API).

**C. `qrcodegen` 1.8.0 — zero-dep fallback**
- Version: 1.8.0. License: MIT. Repo: https://github.com/nayuki/QR-Code-generator
- Maintenance: dormant-stable since 2022-04-17; ~10M downloads; no deps to audit.
- Why: nayuki's high-quality encoder port; manual `get_module(x, y)` loop gives full control over GPUI canvas drawing without an image/SVG bridge.
- Usage pointer: https://crates.io/crates/qrcodegen — `QrCode::encode_text(...)` then iterate modules to draw rects (see repo `rust/` examples).

**Explicit non-pick:** `qrcode-svg` 2.1.1 (MIT OR Apache-2.0, 2026-09-16, repo `houseme/qrcode-rs`) — active, but depends on `qrcode-core`/`qrcode-render ^2.1.1`, i.e. the houseme fork, not kennytm `qrcode`. Only relevant if you adopt that fork. Source: https://crates.io/api/v1/crates/qrcode-svg

### 2. Sparkline / mini-chart for gpui-kit 0.6

**A. gpui-kit native chart + hand-rolled canvas — primary (RECOMMENDED)**
- Version: gpui-kit 0.6.6 / gpui-component 0.6.6. License: Apache-2.0. Repo: https://github.com/longbridge/gpui-kit
- Maintenance: very active (published 2026-09-21).
- Why best: zero new deps, GPU-native 120fps path, theming/accessibility for free; README advertises "built-in charts" and ships a `system_monitor` example for real-time CPU/memory charts; recipe is single-dep `gpui-kit = "0.6"` (pins matching GPUI, re-exports base/component/assets).
- Usage pointer: README Examples on https://github.com/longbridge/gpui-kit — `cargo run -p system_monitor`; docs https://gpui-kit.com. Verify whether the built-in chart covers line/area sparkline; otherwise draw polyline via GPUI Path/canvas in a `gpui-base` element (no chart lib needed for ~50-point sparklines).

**B. `plotters` 0.3.7 — export/offscreen only (CONDITIONAL)**
- Version: 0.3.7. License: MIT. Repo: https://github.com/plotters-rs/plotters
- Maintenance: mature; 2024-09-08; ~234M downloads.
- Why: full charting (axes/legends/mesh) with bitmap + SVG backends; render offscreen to PNG buffer, then display bytes in GPUI image or save to file.
- Usage pointer: https://docs.rs/plotters — `ChartBuilder::on(&root).build_cartesian_2d(...)` + `BitMapBackend`; raster via https://crates.io/crates/image (0.25.10).
- Caveat: overkill inside a 60×20px sparkline cell; adds CPU raster per frame if misused. Inference.

**C. Explicit non-picks:** `sparkline` 0.1.1 (MIT, 2015, ~12K dl — dead); `leptos-sparkline` (Leptos-only); `embedded-graphics-sparklines` (embedded-only). Sources: crates search `sparkline` + https://crates.io/api/v1/crates/sparkline

### 3. Tempfile / temporary file handling

**`tempfile` 3.27.0 — canonical (RECOMMENDED, no serious rival)**
- Version: 3.27.0. License: MIT OR Apache-2.0. MSRV 1.63. Repo: https://github.com/Stebalien/tempfile
- Maintenance: active (2026-03-11); ~840M downloads; owner Stebalien.
- Why best: cross-platform secure temp files/dirs, auto-delete semantics (`tempfile()` OS-unlinked vs `NamedTempFile`/`TempDir` destructor-based), `Builder` (prefix/suffix/rand_bytes/permissions), `persist`/`keep`, `spooled_tempfile` (memory→disk spillover), default `getrandom` reseeding against filename-prediction DoS.
- Usage pointer: https://docs.rs/tempfile/latest/tempfile/ — `tempfile()?` + `writeln!`; `NamedTempFile::new()` + `reopen()`; `tempdir()` + `dir.path().join(...)` + `dir.close()`; security notes (cleaners, umask/world-readable dirs, early-drop pitfall).
- Rejected: `tempdir` 0.3.7 (2018, merged into `tempfile::TempDir`); `cap-tempfile` (capability-based, `bytecodealliance/cap-std` niche — only if capability sandboxing is a requirement).

### 4. Aho-Corasick multi-pattern matching

**A. `aho-corasick` 1.1.5 — canonical (RECOMMENDED)**
- Version: 1.1.5. License: Unlicense OR MIT. MSRV 1.60. Repo: https://github.com/BurntSushi/aho-corasick
- Maintenance: active (2026-08-03); ~1.18B downloads; also powers `regex`/`grep-searcher`/ripgrep.
- Why best: linear-time multi-substring search, configurable space/time, ASCII-case-insensitive, overlapping vs `MatchKind::LeftmostFirst/LeftmostLongest`, stream search/replace, SIMD prefilters (disable via `prefilter(false)` for predictable benches), `no_std` (`alloc`) path.
- Usage pointer: https://docs.rs/aho-corasick/latest/aho_corasick/ — `AhoCorasick::new(patterns)` + `find_iter(haystack)` → `(pattern(), start(), end())`; builder `.ascii_case_insensitive(true).match_kind(...)`; `try_stream_replace_all(rdr, &mut wtr, replace_with)`.

**B. `memchr` 2.8.3 — small-pattern complement (RECOMMENDED alongside, not instead)**
- Version: 2.8.3. License: Unlicense OR MIT. Repo: https://github.com/BurntSushi/memchr
- Why: SIMD 1–3 byte / single-substring search; already the optional `perf-literal` prefilter inside aho-corasick. Reach for it directly when pattern count is tiny and hot.
- Usage pointer: https://docs.rs/memchr + `aho-corasick` crate-features section (`perf-literal`, `std`).

**C. `daachorse` 5.0.0 — large static-dictionary alternative (CONDITIONAL)**
- Version: 5.0.0. License: MIT OR Apache-2.0. MSRV 1.77. Repo: https://github.com/daac-tools/daachorse
- Maintenance: active (2026-08-08); ~6.3M downloads.
- Why: double-array Aho-Corasick — compact + fast for 10K+ patterns (domain/block lists); heavier build and less flexible match semantics than BurntSushi's crate.
- Usage pointer: https://crates.io/crates/daachorse — evaluate only if benchmarks show automaton memory/build pain.

**Rule:** real regexes → `regex` 1.13.1 (MIT OR Apache-2.0, 2026-07-15, https://crates.io/api/v1/crates/regex); literal sets → `aho-corasick`; ≤3 needles hot loop → `memchr`. Inference.

### 5. `getrandom` + `zeroize` for secrets

**A. `getrandom` 0.4.3 — entropy (RECOMMENDED)**
- Version: 0.4.3. License: MIT OR Apache-2.0. MSRV 1.85. Owners: `rust-random` (`dhardy` + maintainers). Repo: https://github.com/rust-random/getrandom
- Maintenance: active (2026-06-17); ~2.1B downloads; 100% documented.
- Why best: thin cross-platform OS CSPRNG wrapper (Linux `getrandom`/`/dev/urandom` fallback, Win10+ `ProcessPrng`, Apple `getentropy`/`CCRandomGenerateBytes`, WASI/EFI/RDRAND opt-ins); `no_std`-friendly; `rand` 0.10.x builds on it.
- Usage pointer: https://docs.rs/getrandom/latest/getrandom/ — `getrandom::fill(&mut buf)?`; `u32()`/`u64()`/`fill_uninit`; `wasm_js` + `getrandom_backend` cfg documented for edge targets.
- Higher-level alternative: `rand` 0.10.3 (MIT OR Apache-2.0, 2026-09-20, https://crates.io/api/v1/crates/rand) when you need distributions/RNG adapters rather than raw bytes.

**B. `zeroize` 1.9.0 — memory clearing (RECOMMENDED)**
- Version: 1.9.0. License: Apache-2.0 OR MIT. MSRV 1.85. Repo: https://github.com/RustCrypto/utils
- Maintenance: active (2026-06-12); ~719M downloads; pure-Rust (`write_volatile` + fences), `no_std`, WASM-tested, `zeroize_derive` opt-in.
- Why best: compiler won't optimize the wipe away; covers scalars/slices/`Vec`/`String` (capacity caveats documented); explicit non-goals (registers/mlock) keep it auditable.
- Usage pointer: https://docs.rs/zeroize/latest/zeroize/ — `secret.zeroize()`; `Zeroizing::new([0u8; N])` auto-wipe on drop; `#[derive(Zeroize, ZeroizeOnDrop)]` (+ `#[zeroize(skip)]`).

**C. `secrecy` 0.10.3 — secret wrapper (RECOMMENDED for app-level secrets)**
- Version: 0.10.3. License: Apache-2.0 OR MIT. Repo: https://github.com/iqlusioninc/crates/tree/main/secrecy
- Maintenance: stable (2024-10-09); ~168M downloads; `forbid(unsafe_code)`; dep `zeroize ^1.6`.
- Why best: makes access explicit/auditable (`ExposeSecret`/`ExposeSecretMut`), blocks `Debug` leaks, wipes on drop; opt-in `serde` without default `Serialize` (anti-exfiltration).
- Usage pointer: https://docs.rs/secrecy/latest/secrecy/ — `SecretBox`/`SecretString`/`SecretSlice`; re-exports `zeroize`.
- Non-pick: `redact` 0.1.11 (log redaction only — solves logging, not memory zeroing).

### 6. `icacls` alternative for file perms (Windows)

**A. `std` — readonly flag only (BASELINE)**
- What: `std::fs::set_permissions` + `std::os::windows::fs::OpenOptionsExt`. Fact.
- Limit: cannot express user/group ACL grants/denies — Windows has no user/group/world bits; it has per-SID DACLs. Inference (platform semantics) + std docs.
- Usage pointer: https://doc.rust-lang.org/std/fs/index.html — use for the trivial readonly case only.

**B. `windows` 0.62.2 — real ACLs (RECOMMENDED for icacls parity)**
- Version: 0.62.2. License: MIT OR Apache-2.0. MSRV 1.82. Repo: https://github.com/microsoft/windows-rs
- Maintenance: active (2025-10-06); ~340M downloads; Microsoft-owned.
- Why best: direct access to `SetNamedSecurityInfoW`/`SetSecurityInfo` + `ConvertStringSecurityDescriptorToSecurityDescriptorW` for `icacls /grant[:r] /deny /reset`-equivalent DACL edits; no stale `winapi` pin.
- Usage pointer: https://crates.io/crates/windows + semantics https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls. Exact module path (`Windows::Win32::Security::Authorization::...`) to confirm at implementation time against the pinned `windows` version. Assumption.
- Context: most Windows programs never touch DACLs and rely on inherited per-user temp dirs; only reach for explicit ACLs when the file must survive a shared directory or match `0600`-equivalent owner-only semantics. Inference, consistent with https://users.rust-lang.org/t/windows-create-file-readable-by-other-users/129728 discussion.

**C. Stale wrappers — avoid for new code**
- `windows-acl` 0.3.0 (MIT, 2021-01-11, https://github.com/trailofbits/windows-acl, ~1.3M dl): ergonomic Trail of Bits wrapper, but unmaintained ~5y. Background: https://blog.trailofbits.com/2018/08/23/introducing-windows-acl-working-with-acls-in-rust
- `windows-permissions` 0.2.4 (MIT, 2021-06-29, safe SID/ACL wrappers, ~928K dl): same staleness verdict.

**D. Fresh niche — audit before adopting**
- `secret-write` 0.1.3 (MIT, 2026-08-08, ~241 dl, repo `Abdk4Moura/filament`): atomic + `0600`/Windows-ACL secret writes — closest semantic match to "secret file with owner-only perms", but negligible adoption. Source: https://crates.io/api/v1/crates/secret-write
- `filp` 0.3.1 (MIT, MSRV 1.85, 2026-08-31, ~75 dl): cross-platform perm management. Source: https://crates.io/api/v1/crates/filp
- `windows-sddl` 0.1.4 (MIT, MSRV 1.74, 2026-09-06): pure-Rust SDDL/SD/ACL/ACE/SID parser for DFIR — parse/audit only, does not apply ACLs. Source: https://crates.io/api/v1/crates/windows-sddl
