# ManyProxy (v1)

Local-only proxy library: store configs, import share links, refresh subscriptions, and serve each config on its own `127.0.0.1:<port>` endpoint (SOCKS5 + HTTP). No system proxy, TUN, DNS, or routing changes — ever.

> Screenshots: [app window with library list] · [Add dialog] · [Import dialog with preview] · [Subscriptions dialog] _(placeholders — fill in live)_.

## Install / run

Windows 10/11 64-bit (v1 platform).

1. Put the app exe plus sidecar binaries **in the same folder** (portable or installed, either works as long as they sit together): `sing-box`, `sing-box-awg` (AmneziaWG/Noise/XHTTP rows only), `xray` (Xray-only VLESS bridge only), plus at most one user-supplied extra-core executable (app dir only). Resolution is app-dir first, then `PATH` (`resolve_engine_binary*`, `src/engine.rs`). Verified by `missing_binaries_state_never_downloads`.
2. Run: `cargo run` (dev) or launch the built exe. No admin needed for default (loopback) use; no registry keys, services, or drivers (`PACKAGING-NOTES.md`).
3. Data lives in a local user-owned SQLite file; logs/health are session-only (`src/store.rs`, `src/health.rs`; tickets 06/12/13).

## Add your first config manually

Toolbar **Add** (`add-config`, `src/main.rs:2878`) → dialog **Add proxy configuration** with fields Name, Protocol (default `vless`, `DEFAULT_PROTOCOL`), Params (optional JSON), Group (default `default`, `DEFAULT_GROUP`), Bind address (default `127.0.0.1`, `DEFAULT_BIND`), Port (**blank = auto**, placeholder `Port (blank = auto)`; auto range `10801–10999`, `AUTO_PORT_START/END` in `src/store.rs`). Confirm with OK (mouse) or the Confirm key — both run the same `DialogCommit` closure (ticket 18, `dialog_footer`, `src/main.rs:242`). Success toast: `Added "<name>"` (`config_added_message`); invalid input keeps the dialog open with an error notification. Edit/Delete work the same way via **Edit** (`edit-config`) / **Delete** (`delete-config`, confirm names the config via `delete_confirm_text`); toasts: `Updated …` / `Removed …`. Select a row and toggle with the Enabled switch or **Toggle** (`toggle-enabled`).

## Import links / files / clipboard

Toolbar **Import** (`import-config`) opens **Import proxy configurations**: paste box (placeholder `One share link per line, JSON, or a WireGuard conf`) + Group field + live inline preview `X valid · Y invalid` (`import_preview_counts`, `import_preview_message`, `src/main.rs:570`; never a toast). One line per item; blank lines skipped.

- **Accepted formats** (`src/import.rs`): `vless://`, `vmess://` (URI + legacy base64-JSON), `trojan://`, `ss://` / `shadowsocks://` (all three grammars), `hysteria2://` / `hy2://` (omitted port → 443) / `hysteria2+realm://`, `hysteria://` (v1, port required), `tuic://`, `wireguard://` URI, `awg://` / `amneziawg://` / `amnezia-wg://`, `socks://` / `socks5://`, `http://` / `https://`, `anytls://`, `naive://` (omitted port → 443), `throne://add/<base64-outbound-json>`, sing-box outbounds JSON arrays / full configs / single outbound objects, Xray `protocol`-shaped objects, SIP008 `servers[]` (typeless method+password infers Shadowsocks), limited Clash YAML `proxies[]` (ticket 15, `import_text`), WireGuard `.conf` (one config per `[Peer]`, names `<stem>-p<N>`).
- **Files:** drag-drop files onto the app window (`on_drop`, `src/main.rs:2865`); one dropped `.conf` keeps its stem via `file_hint`; multi-file drops keep per-file stems/keys (`ImportForm::new_multi`, ticket 16). Pasted text that looks like a conf parses the same way (ticket 15).
- **Clipboard:** toolbar **From clipboard** (`import-clipboard`) prefills the same dialog from clipboard text (`open_import_from_clipboard`, `src/main.rs:1836`); empty clipboard warns `Clipboard has no text to import`.
- Commit rules: valid items land as **disabled** records in the chosen group; per-item failures list `item N (label): reason` (`format_import_failures`) — partial success closes with failures listed, total failure stays open (ticket 14); identical re-imports add nothing (identity: protocol + params, `commit_batch`); import never starts anything.

`throne://addsub/…` single lines divert to subscription intake instead (record + immediate first refresh); malformed ones report the original reason (`addsub_error_message`, `is_addsub_attempt` / `parse_addsub_link`). Edited dialog group wins over payload group (`effective_addsub_group`, ticket 16).

## Subscriptions + auto-refresh

Toolbar **Subscriptions** (`subscriptions`) → manager dialog: Label, Subscription URL, Group, **Auto-refresh** checkbox (default on, `SubForm`, `src/main.rs:774`). Each row shows label, redacted URL (query/fragment/userinfo stripped, `redact_subscription_url`), group, member count, auto flag, last error, plus per-item failures (`sub-failures-<id>`, `subscription_failures_text`), with **Refresh** / **Auto on|off** / **Remove** buttons (`subscription_row`, `src/main.rs:827`).

- Refresh fetches over the platform HTTP client (`fetch_subscription_body`: 8 MiB cap, 20 s timeout, UTF-8 required; errors generic, never echo the URL), parses with the same grammar pack, merges owned members only: renames preserved, no duplicates, upstream removals only unown (hand rows untouched), failures keep last-good with `last_error` (ticket 04, `refresh_with_body` tests).
- Auto-refresh: startup pass over subs due for >24 h (`due_for_refresh`, `DEFAULT_AUTO_REFRESH_SECS = 86400`, `src/store.rs:578`) plus a 5-minute background due-sub tick coalesced into at most one toast (`coalesced_refresh_message`, `DUE_SUBSCRIPTION_TICK_SECS = 300`, `src/main.rs:53/642`); manual Refresh notifies immediately.

## Start / stop / start-all

Detail bar per selected row: **Start** (`engine-start`) / **Stop** (`engine-stop`); toolbar **Start all** (`engine-start-all`) / **Stop all** (`engine-stop-all`). Start regenerates one combined config, runs engine `check`, then restarts the sidecar; start sets enabled, stop clears it (ticket 05, `commit_start_selected` / `commit_start_all` / `stop_all_engines`, `src/main.rs:1247/1327/1351`). Honest toasts: empty library → `Nothing to start — the library is empty`; nothing running → `Nothing to stop — no endpoints are running`; stop-on-stopped → `"<name>" is already stopped` (`start_all_message` / `stop_all_message` / `already_stopped_message`). Background ticks: 5 s engine poll (crash flagged next tick), 60 s re-probe of running rows (`ENGINE_POLL_TICK_SECS`, `REPROBE_TICK_SECS`, ticket 12).

## Pointing apps at endpoints

Each running config serves its own endpoint. Select a row → **Copy URLs** (`copy-urls`) copies both forms (`proxy_urls`, `src/store.rs:227`):

```text
socks5://127.0.0.1:10801
http://127.0.0.1:10801
```

(bind + port only — never credentials, asserted by `copy_urls_carry_binds_not_secrets`). Point the app at the matching form: browsers/clients with separate SOCKS5 vs HTTP fields take the respective line; apps with one "proxy" field usually take the `http://…` line. Keep Bind at the default `127.0.0.1` unless you mean to expose the endpoint.

## Health testing

Detail bar **Test** (`health-test`: URL test of the selected running endpoint) / **Ping** (`health-ping`: TCP ping); toolbar **Test all** (`health-test-all`) tests every running endpoint. Target is the user-visible default `http://www.gstatic.com/generate_204` (`DEFAULT_TEST_URL`, `src/health.rs:38`); http-only, https targets get a named error. Rows show `87ms` / `dead` summaries (`LibraryDelegate.health`, ticket 06); status bar shows `health: N live · M dead` (`health_status_text`); latest samples persist across restart (`record_and_persist`, ticket 12). Stopped rows warn `"<name>" is not running`; empty test warns `No running endpoints to test`. **Logs** (`logs-open`) opens per-selected-config (or global) sidecar lines with a filter field (`open_logs_dialog`); secrets redacted at ingest (`LogStore::push_raw`).

Search: the library list is searchable (`searchable(true)`); one query matches name, protocol, group, bind, port, and upstream `server`/`address` in params — never credential fields (`library_row_matches`, `src/main.rs:690`).

## Export

Toolbar **Export** (`export-library`) → **Export library** confirm showing the plaintext-secret warning verbatim (`export_warning_text`, `src/store.rs:243`: _"Export carries private keys, tokens, and passwords in plaintext. Anyone with this file can use your proxies — store it somewhere safe."_) plus a preview `N config(s) → <path>` and an overwrite note when the file exists (`export_preview_description`, ticket 17). Confirm writes JSON (configs + subscriptions) to `Store::default_export_path()` — `MANYPROXY_EXPORT` override, else `manyproxy-export.json` next to the library file; cancel writes nothing (`commit_export`, `src/store.rs:1376`). Success toast is honest about re-importability: `Exported N config(s) [(M importable)] to <path>` (`export_count_message`, tickets 11/16). The payload round-trips through the import grammar (re-import = 0 added / N duplicates; hand-made metadata-only rows stay backup-only, never poison import).

## Troubleshooting

- **Missing engine binaries:** start fails with a typed error naming the rows + expected file + every directory searched, ending in `ManyProxy never downloads executables silently` (`EngineError::MissingBinary`, `src/engine.rs:335`). Fix: place `sing-box` / `sing-box-awg` / `xray` / your extra-core executable next to the app exe (or on `PATH`). A quarantine hit on a sidecar surfaces the same way — never a silent fallback (`PACKAGING-NOTES.md`).
- **Port conflicts:** the second start fails naming both configs; the first keeps serving (ticket 05, engine conflict check + `QUICKSTART-RUN.md` scenario B). Fix: Edit one row's Port (blank = fresh auto port in 10801–10999).
- **LAN confirm:** any non-loopback bind (`0.0.0.0`, `::`, any non-loopback literal, `requires_lan_confirm`) stops at an explicit confirm dialog naming the config + bind before anything starts (single: `open_lan_confirm_single`; start-all: one dialog naming every LAN-bound row, `lan_confirm_description`). Dismissing changes nothing. Add/Edit dialogs show an inline hint `Starting on <bind> needs a LAN confirm — anyone on the network could use it` (`lan_hint_for_bind`); post-start a warning toast fires (`warn_for_lan_binds`). Firewall prompts for LAN binds are the OS's own and expected.
- **Empty-list refresh:**Reload failures notify (`Cannot load library: …`, `reload`, `src/main.rs:1061`) — a broken database never renders as a silent empty list (ticket 14); background ticks stay silent by necessity (`reload_quiet`). If the list shows `No proxy configurations yet`, the store really is empty (or unreadable — in which case a toast says so).
- **Subscription refresh failed:** row keeps last-good members and records `last error`; per-item failures render inline (`sub-failures-<id>`). Common causes: unreachable URL, non-2xx status, >8 MiB body, non-UTF8 body (`fetch_subscription_body`).
- **No running endpoints to test / "<name>" is not running:** start the row first; health only covers running endpoints (`active_health_rows`).
- **AV / SmartScreen:** unsigned fresh binaries + sidecar spawning + loopback listeners routinely trip heuristics; mitigations are signing, published SHA-256 hashes, no packers (`PACKAGING-NOTES.md`). Never disable AV — verify the quarantined filename against the missing-binary error instead.

## What is explicitly NOT in v1

No system proxy switching, no TUN / virtual interface, no OS DNS rewrite, no routing-rule editor, no admin/elevation path, no auto-update that replaces binaries, no telemetry (only user-initiated subscription fetches + probes through your own endpoints to the visible test URL), no silent binary downloads (asserted by `assert_no_system_mutation` scan over every generated config, `binary_resolution_never_elevates_or_downloads`, `missing_binaries_state_never_downloads`; `QUICKSTART-RUN.md` prohibitions). Live distinct-egress / OS-snapshot-diff verification stays manual per `QUICKSTART-RUN.md` scenarios A–D.
